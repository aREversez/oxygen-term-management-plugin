# Changelog

All notable changes to the Term Management plugin are documented here.
Format loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## Unreleased

### Added
- **AI suggestions are requested in batches with termbase context.** Blank entries are sent 20 terms per request instead of one request per term. Each request carries up to 20 complete source/target pairs of the same termbase (spread over the whole file, at most 2000 characters, one-line entries of at most 80 characters per side) so the model can tell the subject domain and match the termbase's wording; the pairs sit in the system message, identical for every batch, so they are sent once per batch rather than once per term and a provider can cache them. The terms of a batch are sent as a numbered JSON object and the reply is matched to terms by number. A term the model skips is asked again on its own, and those follow-up requests carry only a trimmed reference block (5 pairs, at most 500 characters) — the full one has already been sent with the batch. Note that this sends existing termbase pairs, not only the blank terms, to the configured API address; both user guides now say so. A batch request also states its reply budget (`max_tokens` = 200 + 30 per term), because a batch answer is roughly twenty times as long as a single one.
- **Undo of a TBX delete now restores the whole entry.** When a TBX save removes a termEntry, the node (definition, notes, `termNote`s, further languages, `ntig/termGrp` structures) is serialized into a bounded in-memory stash (most recent 200 per file, 20 files; memory only, tied to the language pair in force). An entry brought back by Undo carries what the deleted node was known by (id, or source/target fingerprint plus position); the next save finds the stashed node, puts it back next to its list neighbour with the terms updated to the entry's current text, and spends the stash item. If the id has meanwhile been taken (for example by an entry added after the delete) the restored node gets a fresh id; if the stash no longer has the node (Oxygen restarted, more than 200 deletions, language pair changed) the entry returns as terms only, appended to the end, exactly as before. The delete confirmation and the user guides say so. Two existing tests that pinned the old terms-only/appended behaviour now pin the stash-less fallback.
- **Per-termbase language pair.** A new "Languages..." button on Preferences > Term Management lets you choose which two languages of a termbase are the source and the target. CSV/XLSX: any two header columns (the status column excepted); the remaining columns, including the other languages, are read as extras and written back at their original positions, so a save never reorders the file. TBX: the langSets with the chosen `xml:lang` values (case-insensitive); entries that have neither chosen language are not shown and survive saves untouched, and a missing source or target langSet is added only when you type a term for it. The choice is stored per termbase; without one nothing changes (first two columns / first two langSets, byte-identical saves). If the file no longer offers a chosen language the default pair is used and the termbase list says so. Changing the pair reloads the termbase and voids a pending "undo delete".
- **Optional English word-form matching ("Match inflected forms").** A new Preferences checkbox (default off) makes a scan also look for the regular forms of the last word of each matched term - plural (`grid` -> `grids`, `mesh` -> `meshes`, `study` -> `studies`), past/participle (`solved`, `gridded`) and -ing (`solving`, `gridding`) - plus a small table of common irregular plurals (`matrix` -> `matrices`, `vertex`, `index`, `axis`, `analysis`, ...); acronyms only take `s` (`CPU` -> `CPUs`). The reported range covers the word actually present, the result still names the termbase entry, and status and replacement suggestions apply as usual; forms obey the word-boundary rule. The rules live in `InflectionVariants` (no stemmer library); comparatives and adverbs are not covered. With the option off the scan is unchanged. When an entry and one of its longer forms both match from the same spot (possible only for terms that contain CJK text, which have no word boundary), the longer hit now replaces the shorter one.
- `TermEntry` now carries unmapped data through edits: `extraFields` for columns beyond source/target (CSV/XLSX) and unmapped TBX fields, and `entryId` for the TBX `termEntry` id. `TermEntry.copy()` deep-copies both, and the panel and context-menu edit paths use it instead of rebuilding an entry from its two visible columns.
- `TermbaseConfig.extraColumns` remembers the header names from the third column on (runtime state, re-detected on load, never persisted).
- New `AtomicFileWriter`: saves fill a temporary file in the target's directory and move it over the target when complete, so a failure half-way leaves the previous file untouched and no temporary file is left behind; a move blocked by another application is reported as "file in use".
- CSV saves are lossless: columns from the third on are read into entries, written back in the original header order on save, and saves now go through `AtomicFileWriter` (UTF-8 BOM and blank-row skipping unchanged). Two-column files gain no new column.
- XLSX saves are lossless: the original workbook is reopened and only the first sheet's data rows are rewritten, so other sheets, header-row styles and column widths survive; extra columns are read into entries and written back like CSV. Known limitation: per-cell formatting on data rows is not preserved. If the original file cannot be opened, a new workbook is written instead (logged to the plugin console).
- TBX saves are lossless: the file on disk is re-parsed and matched by `termEntry` id, so `descrip`, `note`, `termNote`, additional languages and the original ids survive an edit or a no-op save; only the term text of the same two langSets the loader reads is replaced. New entries get collision-free ids, deleted entries are removed, and whitespace normalisation makes repeated saves byte-identical (no more blank-line growth). The DOCTYPE's external DTD declaration is preserved; a DOCTYPE internal subset is not (known limitation).
- Editing a term no longer overwrites changes made to the termbase file outside the plugin: the registry remembers when each cached file was last written (timestamp + size) and re-reads the file first if it changed on disk before applying the edit. Editing after the file was deleted now fails with an explicit error instead of silently recreating it.
- New "Case sensitive matching" checkbox on Preferences > Term Management (off by default, persisted with Oxygen's options storage): when enabled, document scans no longer match a term against text that differs only in letter case. The setting applies to the recognition panel and is honoured across restarts even if Preferences is never opened.
- Term maturity status (`preferred`, `admitted`, `deprecated`) is now modelled end-to-end in the storage layer. CSV and XLSX files use a column named `status` (case-insensitive header match); TBX files use `termNote type="administrativeStatus"` with TBX-Basic domain values (`preferredTerm-admn-sts`, `admittedTerm-admn-sts`, `deprecatedTerm-admn-sts`). Unknown values survive round-trips verbatim; files without a status column are never altered; the column/termNote appears only when at least one entry actually carries a status. `TermEntry.getStatus()` returns the parsed enum (or null), `setStatus()` and `getStoredStatusValue()` support the UI and handlers, and `copy()` preserves the status.
- Status is visible and editable in the UI: the Terminology panel now shows a read-only "Status" column beside Source and Target; the Add/Edit dialog includes a status dropdown (Preferred / Admitted / Deprecated) and, when the entry already has a note, an editable Note field. The Recognition panel adds a "Status" column to its results table, and deprecated terms are highlighted in red in the author-mode overlay instead of the normal yellow.

### Fixed
- Cancelling an AI suggestion run now closes the progress dialog at once and abandons the request in flight (no more tokens spent), instead of waiting for the model's reply; closing the dialog's window cancels too. The abandonment now covers the whole request: cancelling while the response body is still arriving stops the read instead of leaving the worker thread blocked on the socket until the stream ends (the 30 s request timeout only reaches up to the response). A run whose dialog you closed at the very moment it finished is no longer discarded silently either — the suggestions it paid for are shown, because the review now follows the worker's real state rather than the cancel flag.
- A batch reply that was cut off by the token limit no longer voids the whole batch. Previously `finish_reason=length` threw away every answer the batch had already produced and the run fell back to one request per term, each carrying the full reference block again — a single truncation turned one request into twenty-one, and three such fallbacks stopped the entire run. The complete `"number": "translation"` pairs before the cut are kept and only the terms with no answer are re-asked. The same rescue applies when a reply is not one parseable JSON object (prose around two objects). A single-term reply that was cut off is still rejected: half a translation cannot be offered as one. Answers whose value is a JSON boolean or number instead of a string (`{"2": true}`) are no longer turned into the text "true".
- The terms that got a suggestion are now listed in table order even when a later fallback request filled an earlier gap, so the review dialog and the terminology table no longer disagree about the order. The progress bar also keeps moving while fallback requests run instead of stalling at batch boundaries.
- An AI suggestion that never came back is no longer dropped without a trace: the review dialog names the terms that stay blank and why (empty reply, timeout, HTTP error), or that the run stopped after repeated failures. Replies that are only reasoning (`<think>` blocks), have no text (`null` content) or were cut off by the token limit are rejected with their own reason instead of being offered as a translation.
- Right-clicking inside a multi-row selection in the Terminology table no longer collapses it to the clicked row, so "Delete Term" in the context menu deletes every selected row (the toolbar button already did). A right-click on an unselected row still selects just that row.
- A Latin term written right next to Chinese, Japanese or Korean characters is now recognized again (e.g. `FEA` in `使用FEA。`). The word-boundary check used to treat CJK characters as letters and rejected every such occurrence; letters from other languages still block a match, and a term next to digits behaves as before.
- Scans no longer bury a long term under its own fragments: when a shorter hit lies fully inside a longer one (e.g. 弯曲 and 刚度 within 弯曲刚度), only the longer hit is reported. Equal spans and partial overlaps are still reported separately.
- A source term with several translations now lists every translation for the same occurrence; previously only the first one survived deduplication. Identical (source, translation, position) hits coming from two loaded termbases are still reported once.
- Text-mode scans no longer report hits inside XML markup. Tags, attributes, comments, processing instructions and the DOCTYPE are blanked out before matching (at identical offsets), so a term that only occurs as an element name or attribute value is no longer flagged; text content, including CDATA content, is matched as before.
- The word-boundary check now also rejects letters written outside the Basic Multilingual Plane (e.g. mathematical bold 𝐀 before `FEA`); a regex look-around only saw one UTF-16 code unit of such a letter and let the occurrence through.
- **TBX saves no longer lose data (P0).** Three save gaps are closed: (1) a `termEntry` without an `id` is no longer treated as new — it keeps its document position and its `descrip`/`note`/other children survive a no-op save; (2) entries the loader skips (e.g. a `termEntry` with only a `descrip` and no readable term) are no longer deleted on save — only nodes the loader would actually produce are eligible for removal; (3) clearing a translation and saving, then reloading, keeps the right language pair — `selectLangSets` now matches langSets structurally (has `xml:lang` and a `tig/term` or `ntig/termGrp/term`) instead of skipping empty terms, so a third language is no longer mistaken for the target.
- **XLSX refuses to overwrite an unopenable file (P0).** When the termbase file exists and is non-empty but the workbook cannot be parsed, the save now throws with the underlying reason instead of logging to stderr and replacing the file with a fresh two-column workbook.
- **Term status can be cleared (P1).** `setStatus(null)` is now distinguishable from “never edited” (empty-string sentinel): a cleared status writes an empty CSV/XLSX cell and removes the TBX `termNote type="administrativeStatus"`, rather than silently reverting to the value read at load time.
- **TBX `ntig`/`termGrp` status now works (P1).** Administrative status is read and written for both `tig/term` and `ntig/termGrp/term` structures; it previously failed silently on `ntig` entries. Note the semantics differ by format: in TBX the status is bound to the source-language term, while in CSV/XLSX it is a per-row column.
- **Edit dialog no longer writes on no-op (P1).** Confirming an entry whose status dropdown was left on the default no longer stamps `preferred` or adds a `status` column to a file that had none.
- **External-change detection is background and correct (P1).** Checking for external changes on tab activation no longer reloads on the UI thread (large termbases froze the interface); the reload tooltip is cleared when leaving the tab; the on-disk stamp is now read *before* the load so a change landing during the load window is not missed; and editing after an external reload now merges the user's edits onto the freshly loaded entry instead of overwriting the external change with a stale copy.
- **Text-mode scans no longer match inside entity names (P1).** `amp` and `lt` no longer hit inside `&amp;` / `&lt;`; a term that legitimately spans or equals an escaped sequence (e.g. `R&D` matching `R&amp;D`) still matches.
- **Deprecated terms are always reported (P1).** A deprecated term that lies inside a longer match is no longer swallowed by longest-match filtering, so the “deprecated” warning still surfaces (it does not, however, affect the containment check for other matches).
- **TBX claiming info is refreshed after every successful save (P0).** Each entry remembered the `termEntry` position and `id` it had when the file was *loaded*. The registry returns the same cached list after a save, so a later edit that reused that list (the panel's undo snapshot, or a cached termbase edited without a reload) claimed the wrong node — deleting one no-id entry shifted every following definition onto the wrong term, and a newly created entry was assigned a fresh `id` on every save. `saveTerms` now writes back each entry's final document ordinal and `id` (including the ids it mints for new nodes), but only after the file has been written, so a failed save leaves the in-memory values untouched; the two fields are `volatile` because the writer thread updates them while the UI thread reads the same objects.
- **A change landing during a load marks the cache stale (P1).** If the file was modified while it was being read, the loader had recorded the post-read stamp, making the half-read content look fresh; the next edit then skipped reloading and clobbered that change. It now records the pre-read stamp in that case, so the following write reloads first and preserves the external edit.
- **TBX saves no longer attach an entry to the wrong node after a delete-and-undo (P0).** An entry without an `id` is matched to its node by document position, and that position goes stale when neighbouring entries are removed; the panel's undo restores a full pre-delete list in which the deleted entry still carries its old position, so it could claim a neighbour's node (moving that neighbour's `descrip`/`note` under the wrong term). A position claim is now accepted only if the node still holds the same source and target text the entry last had on disk (`TermEntry.persistedFingerprint`, set on load and after every successful save); otherwise the entry is written as a new node. Two id-less nodes whose source and target text are both identical cannot be told apart this way (known limitation: they may swap their unmodelled content).
- **Undo Delete no longer overwrites later work (P1).** Undo used to write the whole pre-delete list back to the file, which erased every term added or edited after the delete (and any change another program made to the file in between). It now re-inserts only the deleted terms, each at its old position, into the termbase as it is at that moment, through the same checked update path as every other edit. A term the user has since re-added by hand is not inserted twice. The Undo button is enabled only after the delete has actually succeeded, stays available if the undo itself fails (for example a locked file), and a delete that removed nothing keeps the previous undo. `TermbaseRegistry.saveTerms` is documented as unsafe for editing an existing termbase, and the unused `TerminologyPanel.safeSaveTerms` is removed.
- **External reloads are noticed while you stay on the tab, and announced in the status bar.** The per-tab tooltip hint was never actually seen (it only paints while the mouse lingers on the tab header, where the cursor no longer is after switching) and a title-based hint cluttered the narrow tab headers. A visible watched tab now probes every 2 seconds, so an edit made in another program is reloaded within seconds without leaving or re-entering the tab; the reload is announced through Oxygen's bottom status-bar message, which appears without hovering and never blocks work like a modal dialog does (the message stays until the next Oxygen event replaces it). Only user-initiated tab switches clear the old hints - the periodic probe leaves the passive tab-header hint from an earlier pass standing.
- **The 2-second probe no longer mistakes the plugin's own save for an external change.** A save holds a per-file lock while it writes the file and only *afterwards* refreshes the recorded timestamp; the external-change check read the on-disk stamp without taking that lock, so a probe landing in the gap between the write and the stamp update could report a file the plugin had just saved as "externally modified" and reload it with a misleading notice. The check now holds the same per-file lock across both stamp reads (still outside the registry monitor), so it waits for an in-progress save and then correctly sees no change. Reloading the Terminology table no longer drops the rows the user had selected for an edit or delete: the selection is restored by term after a background reload. The periodic-probe visibility test (panel on screen and a watched tab showing) is factored into a Swing-free predicate. The reload notice is now also translated in the German, French and Japanese string files instead of showing English.
- **Japanese quality-check messages name the two fields the way the rest of the screen does.** The result dialog said 源語用語 / 訳語用語 while the term table, the add/edit dialog and the scan-direction picker all say ソース用語 / ターゲット用語 for the same two columns. The eight `check.msg.*` templates now use ソース用語 / ターゲット用語, so one concept has one name throughout the Japanese UI.
- **The quality-check result dialog is readable and keeps its column order.** Its table auto-resized all four columns to the fixed dialog width, squeezing long cross-termbase messages and absolute paths into unreadable fragments, and dragging the header could reorder the columns. The columns now get sensible preferred widths and scroll horizontally, a cell that is still clipped shows its whole text as a hover tooltip (the same rule the preferences file-name column uses), and header drag-reordering is disabled.
- **An AI-translation suggestion that fails to save now says why.** Accepting suggestions and hitting a write error (most often the XLSX is still open in Excel) showed only `Failed to save suggestions: java.lang.RuntimeException: Failed to save termbase: <path>` - the wrapper's text, with the real cause buried in the exception chain and the table left showing the unsaved edits. The path now reuses the inline-edit error handling: a locked file gets the "close it in the other application" message, any other failure is reported by its root cause, and the table reloads to show what is actually stored.

### Improved
- **The Terminology button bar no longer loses buttons in a narrow sidebar and takes less room.** A plain `FlowLayout` reported a single-row height whatever the width, so the trailing buttons (the AI-translate one especially) were clipped and unreachable when the panel was docked narrow; the rows are now a small wrapping panel that grows its preferred height for however many lines the width needs, so every button stays reachable at any width. The panel reserves FlowLayout's top and bottom vertical gap (an earlier omission clipped the bottom row) and re-lays-out once the real width is known, so a wrap to a second line is never cut off. The AI-translate button's label was shortened (`AI Translate...` across all six languages, the full description staying in its tooltip), the inter-button gap was tightened, and the text buttons use a slightly smaller font with reduced padding on all four sides.
- **Recognition scans use one pass over the document instead of one regex per term (Aho-Corasick).** The whole termbase is compiled into a single automaton and the document is read once, so the cost no longer grows with the number of terms times the document length. Measured on one machine, same inputs, identical hits: 2 000 terms × 100 KB 1.4 s → 0.03 s; 5 000 terms × 200 KB 5.8–7.1 s → 0.05 s; 20 000 terms × 1 MB 112 s → 0.25–0.36 s. Results are unchanged by construction and by test: the previous scanner is kept in the test tree as `ReferenceScanner`, and `DocumentScannerDifferentialTest` compares both over thousands of random termbases and documents (both directions, case on/off, text and Author mode, duplicates, nested and self-overlapping terms, entities and markup, supplementary-plane letters). The static compiled-pattern cache is gone with the regexes it served.
- Recognition scans are faster, not slower: the 20 000-term × 1 MB benchmark runs in about 140 s versus 261–272 s before the matching fixes (an intermediate per-position boundary regex had cost 966 s). The match pattern is now a plain literal and the word-boundary rule is checked in code per hit; compiled patterns are also reused across scans instead of being rebuilt for every panel refresh.
- **TBX saves are now O(N) instead of O(N²).** Node claiming during save uses an `id → queue` map rather than a linear scan of the remaining nodes; a 20 000-entry save dropped from about 3.8 s to well under a second.
- **Atomic saves preserve file permissions and report move failures.** On POSIX file systems the target's permissions are copied onto the temporary file before the move (the default `0600` temp file no longer silently changes them); when the atomic-move fallback's plain replace fails, it is reported as a file-in-use/read-only error like the primary path.
- **The static scan-pattern cache is bounded.** Once it exceeds 50 000 entries it is cleared wholesale, so it can no longer grow without limit across a long session; results are unaffected (the next scan just recompiles).
- Removed dead matching code that no longer had callers: the single-argument `TermMatchUtils.buildMatchPattern(String)`, `TermbaseRegistry.getMatchPattern` and its separate `patternCache` (the surviving `buildMatchPattern(String, boolean)` javadoc now states it builds a plain literal and that boundaries live in `acceptAtBoundary`).

### Added
- New "Check" button on the Terminology tab runs a quality inspection across all enabled termbases (empty source/target, multi-target conflicts, case-only duplicates, consecutive whitespace, cross-termbase conflicts). Results are shown in a non-modal dialog table and can be exported as UTF-8 BOM CSV for Excel. The checker (`TermbaseChecker`) is pure logic with 13 unit tests.
- External-change notification (step 4.2): the view compares each cached termbase’s on-disk stamp when the user switches to the Recognition or Terminology tab and, while such a tab is visible, every 2 seconds; a file modified externally is reloaded and the user is told via a status-bar message. Own saves never trigger this (stamp is updated post-write).
- **Scan by target term for QA (step 3.2).** A new direction dropdown on the Recognition tab switches between the long-standing *by source term* scan and a new *by target term* scan. The target scan matches each entry's translation, so an English text can be swept for translations marked `deprecated` in the termbase. Deprecated hits sort to the top of the results table; a new *Suggested replacement* column lists the preferred/admitted translations of the same source term within the selected termbase; and an *Only show deprecated* checkbox narrows the table, statistics, highlights and navigation to just the deprecated hits (an in-memory filter, no re-scan). The chosen direction is remembered across restarts, and navigation/highlighting key off the side that was actually matched (`ScanResult.matchedText`). The scan kernel matches both directions through one shared path (only the matched side differs), and the suggestion lookup (`ReplacementSuggestions`) is pure logic with unit tests. Known limitations: a deprecated term that is part of a longer legitimate term is still reported (no special suppression), and there is no stemming (`grids`/`gridded` do not match `grid`). Scanning by source term is unchanged.
- **Deleting from a TBX termbase now says what Undo cannot bring back.** A TBX entry holds more than the two terms; deleting it removes its definition, notes and other languages from the file, and Undo restores only the terms (and status), appended to the end of the file. The delete confirmation for TBX termbases now states this (new string `msg.confirm.delete.tbx.note` in all six languages), and the user guide describes it. A new test keeps the six resource files' keys in step.
- **The external-change check is now testable.** The decision logic of the tab-switch check moved out of `TermManagementView` into `ExternalChangeCheck` (reload only the enabled termbases whose file changed; clear every tab hint at the start of each check; show the hint only if something was reloaded and the user is still on the same tab), and `TermbaseRegistry` reads file stamps through a replaceable reader, which lets a test verify that `isExternallyModified` does not hold the registry lock while it touches the disk. No behaviour change.
- **Termbase format conversion (CSV / XLSX / TBX).** A new "Export as..." action on the Terminology tab writes the loaded terms to another format (CSV ⇄ XLSX ⇄ TBX) through `TermbaseConverter`. The converter carries what each target format can represent - source/target terms, the per-termbase language pair, and maturity status (the CSV/XLSX `status` column and the TBX `termNote type="administrativeStatus"` values are converted in both directions); for TBX targets, definitions, notes and unmapped fields are kept as `termNote`s so a TBX→TBX round trip no longer regenerates the document from the two visible columns alone. When a field genuinely cannot survive the target format (a status going into a format that has no status column, notes or extra languages a glossary cannot hold), the export names them in a "content will be dropped" report instead of claiming nothing was lost. Parsing a TBX source is hardened against XML external-entity attacks - the converter shares the termbase handler's secure `DocumentBuilderFactory`/`TransformerFactory` - and a malformed TBX now fails with an error rather than silently exporting nothing. The export refuses to overwrite the source file itself or any registered/enabled termbase, so a conversion can never destroy a library; when the source and target formats are the same, the suggested file name gets a `_export` suffix rather than pointing back at the original.
- **DITA glossary export.** The same export action also offers DITA: the terms are written as a DITA 1.3 `glossgroup` (`glossentry` / `glossterm` / `glossdef`, with the standard DOCTYPE and `@class` values) that Oxygen opens and folds into a map. As with the other formats, fields a `glossentry` cannot hold (status, notes, additional languages) are listed in the drop report rather than lost silently.
- **AI translation suggestions.** When enabled on Preferences > Term Management, entries whose target is blank can be filled through an OpenAI-compatible chat endpoint (`OpenAiHttpTransport`): each source term is sent with its context and the returned translation is shown for review before it is written back. For informed consent the feature sends your source terms to the configured API address, and the API key is stored in clear text in Oxygen's options storage (it is not encrypted) - enable it only against an endpoint you control. Requests follow no redirects (`Redirect.NEVER`, so the `Authorization` header is never forwarded to another host), the reply body is capped at 1 MB by streaming (an oversized or stalled response is cut off rather than buffered whole), and a batch run shows a cancelable progress dialog and requests at most 200 terms per click, so a few hundred blank entries no longer look like a frozen interface.

## 1.0.11 - 2026-07-08

### Fixed
- Icon cache no longer misuses the global `UIManager` defaults table as a cache store; switched to a private, isolated cache map, consistent with the plugin's other caches.
- Fallback resource bundle (`messages.properties`) was out of sync with the other language files (63 vs 150 keys); now kept in sync.
- Removed a duplicate, unused `i18n/` folder left over at the repository root from an earlier packaging attempt.

## [1.0.10] - 2026-07-07

### Added
- Localization coverage extended to ~30 core UI strings across menus, dialogs, and buttons (right-click context menu, Terminology panel, Recognition panel, Preferences page).
- New language support: French, German, Japanese (in addition to existing English/Chinese), matching Oxygen XML Editor's own set of built-in UI languages.
- Plugin UI language now follows Oxygen's configured interface language (via `getUserInterfaceLanguage()`) instead of the OS/JVM default locale.
- `TermbaseRegistry` change-listener mechanism — panels now automatically refresh when terms are added/edited/deleted from any entry point (e.g. right-click Quick Add updates an already-open Terminology panel).
- Compound edit support for "Insert Translation" — the delete-selection + insert-translation sequence is now a single undoable step in Author mode.

## [1.0.9] - 2026-07-06

### Added
- Right-click context menu integration in Author and Text mode: Quick Add, Insert Translation, Edit Term, Search in Termbase.
- Multi-term selection guard — selecting a continuous span of text containing more than one known term now shows a disabled hint instead of allowing an accidental compound "term" to be added.
- Unit test suite for the three termbase format handlers (CSV/XLSX/TBX), 17 tests covering round-trip save/load, encoding edge cases, and malformed/missing-file handling.

### Improved
- Termbase configuration is now serialized as proper JSON via Gson, replacing a hand-written parser.
- Long-running operations (termbase reload, term save/delete, document scanning) now run on a background thread via `SwingWorker`, keeping the UI responsive on large termbases or documents.
- Right-click menu term lookup uses the existing source-term index and caches compiled matching patterns, instead of a full re-scan on every invocation.
- Consistent, user-facing error dialogs for load/save/reload failures, replacing silent console-only logging.

### Fixed
- Crash risk when loading XLSX termbases with a non-text (e.g. numeric) header cell.
- A threading/error-handling conflict where a reload or scan failure could show a background-thread error dialog immediately followed by a contradictory "success" message.
- The "Search in Termbase" menu item could appear enabled but silently do nothing if the Term Management view had never been opened.
- Term Entry dialog allowed confirming with an empty target term; both source and target are now required.

## [1.0.8] and earlier

Right-click context menu (initial version), core Term Recognition / Terminology Management / Termbase Search functionality, TBX/XLSX/CSV format support, Preferences-based termbase configuration. Detailed changelog entries were not tracked prior to 1.0.9 — see git history for full detail.
